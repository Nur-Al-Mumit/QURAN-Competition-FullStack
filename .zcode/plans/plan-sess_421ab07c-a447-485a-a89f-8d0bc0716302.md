# Plan: Make /admin/submit-viva-result Fully Dynamic

Keep the existing design (emerald theme, cover-page-per-examiner, landscape print CSS, table layout) **exactly as-is** — only data wiring and a new Decision column change.

## A. Backend — Laravel

### A1. New migration: link exam-day event to a season
`backend/database/migrations/2026_07_21_000000_add_season_and_phase_to_timeline_events_table.php`
- Add nullable `foreignId('season_id')->constrained()->nullOnDelete()` to `timeline_events`
- Add nullable `string('phase', 50)` (e.g. `"exam_day"`, `"viva"`) so the cover-page query can find the right event per season
- Both nullable so existing rows are unaffected.

### A2. New Eloquent models
- `backend/app/Models/UserPreliminaryResult.php` — fillable: `user_id, user_competition_form_id, season_id, criteria_id, attendance_allocation_id, attendance_status, result_category_id, comment, examiner_id`. Relations: `resultCategory()`, `examiner()` (Admin), `attendanceAllocation()`, `userCompetitionForm()`.
- `backend/app/Models/ResultCategory.php` — fillable: `name, description`.
- Add `userPreliminaryResults()` hasMany to `AttendanceAllocation` (so the controller can eager-load existing decisions).

### A3. New controller `VivaResultController` (admin-authenticated)
`backend/app/Http/Controllers/Api/V1/Admin/VivaResultController.php`, using `Auth::guard('admin-api')` and `JsonResponse` (matches existing admin controllers).

Endpoints (all under `auth:admin-api`):

1. `GET /admin/viva-result/seasons` → reuse pattern from `DashboardController::getSeasons()` (list seasons + `active_season_id`).
2. `GET /admin/viva-result/data?season_id=X` → returns the full dynamic payload:
   - `exam_day` = the `timeline_events` row for `season_id=X` and `phase='exam_day'` (provides `start_date`, `end_date`, `title`); null-safe.
   - `result_categories` = all rows from `result_categories` (`id`, `name`) for the Decision dropdown.
   - `examiners` = `Admin::where('assigned_role',3)->where('is_active',1)->orderBy('id')->get()`, each tagged with a computed letter (`A`, `B`, `C` …) by index.
   - `groups` = `attendance_allocations` for `season_id=X` with `admin`, `userCompetitionForm`, and `userPreliminaryResult` (decision) eager-loaded, grouped by `admin_id`. Each student row carries: `serial`, `reg_no`, `name_en`, `need_training`, `education_background`, `exam_time`, plus `user_id`, `user_competition_form_id`, `attendance_allocation_id`, and the **current** `result_category_id` / `comment` (from existing `user_preliminary_results`, if any).
3. `POST /admin/viva-result/decision` → auto-CRUD upsert. Validates `user_id, user_competition_form_id, season_id, attendance_allocation_id, result_category_id (nullable)`. Uses `updateOrCreate` on `unique(user_id, season_id)` to set `result_category_id`, `examiner_id` (= current admin from `Auth::guard('admin-api')`), `attendance_allocation_id`. Returns the saved row. (Comment can be added later via the same endpoint.)

### A4. Register routes
`backend/routes/api/admin/viva-result.php`:
```php
Route::controller(VivaResultController::class)->prefix('viva-result')->group(function () {
    Route::get('seasons', 'seasons');
    Route::get('data', 'data');
    Route::post('decision', 'storeDecision');
});
```
Include it from `backend/routes/api/admin/api.php` (inside the existing `auth:admin-api` + `admin` prefix group).

## B. Frontend — Nuxt 3

### B1. Rewrite `submit-viva-result.vue` (same design, dynamic data)
- Switch from `useAxios` (guest) to `useAdminAuthenticatedAxios`.
- Add a **season filter header** (print-hidden) matching `dashboard.vue` styling: white card, label "Season", `<select>` bound to `filters.season_id`, defaulting to active season. On change → refetch data.
- `onMounted`: fetch seasons → default to active → fetch `/admin/viva-result/data?season_id=...` → fetch `result_categories` (comes back in the same payload).
- **Cover page** now pulls from `exam_day`:
  - Title keeps `বিশুদ্ধ কুরআন পাঠ প্রতিযোগিতা - ১৪৪৮ হিজরি` heading (unchanged).
  - Exam-day date → `exam_day.start_date` formatted; start/end time → `exam_day.start_date` / `exam_day.end_date` (replacing the hardcoded "2 August, 2025" and the computed range).
  - Examiner name / room number / total students stay the same (per group from `attendance_allocations`).
  - Footer shows the exam-day admin (the supervising admin) — pulled from `exam_day` or examiner list.
- **Per-examiner cover serial letter**: when iterating `groups`, also show the examiner's assigned letter (A/B/C…) which the backend precomputes from active role-3 admins in order.
- **Students table** — same columns + a new **Decision** column (between Exam Time and Comments):
  - Screen: a `<select>` (dropdown of `result_categories`) bound to the row's `result_category_id`, with `@change` calling `saveDecision(student)`.
  - Print: the `<select>` is hidden via `print:hidden`; instead an empty cell is rendered (`print:block`) so the printed sheet has a blank Decision column to be filled by hand.
  - Comments column stays blank for printing (unchanged).
- Keep `getExamTimeRange` as a fallback when `exam_day` is null.
- **All existing classes, emerald colors, cover-page layout, print CSS (landscape `@page`, page-break-after on `.examiner-group`/`.cover-page`/`.attendance-content`, `.avoid-break`) stay identical.** No design changes.
- New: a small `saving` per-row indicator + error toast on save failure (minimal, print-hidden).

### B2. Auto-save composable inline
`saveDecision(student)` calls `POST /admin/viva-result/decision` with the row's ids + chosen `result_category_id`; optimistic UI update, reverts on error. No Save button (per your decision).
